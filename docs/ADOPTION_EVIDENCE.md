# 실제 사용과 피드백 증빙

이 문서는 외부 사용자가 Salesman을 직접 실행하고 남긴 피드백을 수동으로 확인하는 유지관리 안내입니다. 현재 확인된 외부 사용·기여 실적을 주장하지 않습니다. [CSV 서식](adoption-evidence.csv)은 헤더만 있으며, 예시 사용자나 실적 행을 넣지 않습니다. 이 안내와 신청서 초안은 신청 제출·자격 충족·선정을 뜻하지 않습니다.

## 피드백을 받는 순서

1. [실행 안내](../README.md)에 따라 API 키 없이 데모를 실행하도록 안내합니다. 예시 문의의 초안을 수정하고 승인 상태를 확인하는 등 한 가지 작업을 정합니다. 실제 메시지는 발송되지 않습니다.
2. 사용자가 직접 [데모 사용 피드백 / Demo feedback](https://github.com/brucedata/salesman-hackathon/issues/new?template=demo-feedback.yml) 양식을 남기도록 안내합니다. 실행 날짜, 버전 또는 커밋, 시도한 작업, 예상 결과와 실제 결과, 재현 단계를 요청합니다. 실행하지 않았다면 그대로 적도록 합니다.
3. **GitHub 이슈는 공개됩니다.** 실제 고객 문의·연락처·녹음·결제 정보·API 키·로그 원문을 받지 않습니다. 필요한 재현 자료는 가상 데이터로 바꾸고, 스크린샷에서도 계정·개인정보를 가립니다. 보안 문제는 [SECURITY.md](../SECURITY.md)의 경로를 사용합니다.
4. 신청 근거용 익명 집계, 개별 공개 사례 소개, 제한된 상업용 익명 집계는 각각 선택하도록 합니다. 거절하거나 답하지 않아도 버그 제보·지원은 그대로 받습니다. 공개된 이슈라는 사실만으로 신청서·홍보·데이터 제품에 재사용하는 데 동의했다고 간주하지 않습니다.
5. 유지관리자가 실제 내용과 링크, 외부 참여 여부, 중복, 허용 범위를 확인합니다. 오류라면 수정 이슈·PR에 연결하고, 해결 여부를 기존 피드백에 이어 기록합니다. 본인이 재현한 결과와 외부 사용자가 보고한 결과를 구분합니다.

## 서로 다른 지표를 섞지 않기

| 지표           | 기록할 의미                                                      | 이 지표만으로 알 수 없는 것                    |
| -------------- | ---------------------------------------------------------------- | ---------------------------------------------- |
| 스타·포크      | 특정 날짜에 관찰한 관심·복제 수                                  | 실제 실행, 만족도, 기여, 코드 재사용           |
| 외부 테스터    | 유지관리자가 아닌 사람이 직접 실행했다는 확인 가능한 보고        | 유료 고객, 지속 사용, 프로덕션 도입            |
| 작업 성공      | 정한 작업을 성공했다고 보고한 사례; 직접 관찰했다면 별도 표시    | 전체 사용자 성공률, 모델 품질, 매출 효과       |
| 병합된 외부 PR | 외부 기여자가 작성하고 실제 병합된 변경과 링크                   | 이슈·포크만 있는 사람의 기여, 사용자 수        |
| 코드 재사용    | 어떤 프로젝트가 어느 코드·흐름을 어떻게 사용하는지 보여주는 근거 | 데모 방문·호평·포크만으로 확인되지 않는 의존성 |

유지관리자 자신의 테스트, AI·자동화 실행, 예시 데이터, 미실행 응답과 중복을 외부 사용 실적으로 세지 않습니다. 버그 이슈만 있고 실행 여부가 확인되지 않으면 외부 테스터로 분류하지 않습니다. AI가 도운 PR도 실제 작성자·검토·변경 내용에 따라 설명하며, AI나 봇 계정을 별도의 외부 사람으로 세지 않습니다. 사람·실행 사례·작업·PR·재사용 프로젝트의 단위는 각각 다릅니다.

## 동의와 공개 범위

- `evidence_consent`: 업종·시도한 작업·결과·재사용 의향 네 항목을 프로젝트 개선 보고와 신청 근거에 사용할 기간별 익명 집계에 포함하는 것에 대한 명시적 동의입니다. 이슈 제출이나 공개 계정 사용만으로 채우지 않습니다.
- `public_case_permission`: 이슈·프로젝트 링크, 인용 또는 식별 가능한 개별 사례를 신청서나 프로젝트 소개에서 다시 공개하는 별도 허용입니다. 집계 동의와 독립적이며 선택 사항입니다. 실제 허용한 인용·링크·용도 범위를 근거에서 확인합니다.
- `commercial_aggregate_consent`: 양식에서 선택한 **업종·시도한 작업·결과·다시 사용할 의향** 네 필드에 한정한 상업용 익명 집계 허용입니다. 자유 서술, 재현 단계, 인용, 스크린샷, 신원·연락처와 코드·고객 자료는 포함하지 않습니다. 신청 근거용 집계나 개별 사례 소개 동의를 대신하지 않습니다.
- `permission_verification`: 위 선택의 주체·날짜·범위를 실제로 확인했는지 기록합니다. `pending` 또는 근거 없는 동의는 승인으로 처리하지 않습니다. 다른 회사·고객의 자료를 제보자가 대신 허용할 수 있다고 가정하지 않습니다.

동의 규약은 `v1`이며, 동의를 받은 당시의 규약 버전과 이슈 제출 날짜를 함께 남깁니다. 모든 선택 이용은 제출일로부터 12개월 이내에만 새로 수행합니다. 기간이 끝나면 재동의 없이 후속 집계·새 인용에 포함하지 않으며, 해당 작업본의 선택 이용을 중단하고 삭제합니다. 빈 선택은 동의가 아닙니다. 참여자는 원래 이슈의 댓글로 철회를 요청할 수 있고, 확인한 철회는 이후 아직 공개·배포하지 않은 집계와 사례 사용에 반영합니다. 동의 범위가 변경되면 이전 선택을 새 용도로 확대 해석하지 않습니다.

이 저장소와 여기에 커밋한 CSV도 공개됩니다. **작성된 CSV·개별 행·원본·신원 연결표는 저장소에 올리지 않습니다.** 필요한 수동 기록은 접근을 제한한 별도 사본에서 관리하고, 공개 보고에는 허용된 집계만 사용합니다. 개별 공개 사례는 별도 허락을 확인한 링크와 필요한 설명만 제시합니다. 이름·이메일·전화번호·비밀 값은 어느 CSV에도 넣지 않습니다. GitHub 링크를 가진 작업본은 익명 자료로 간주하지 않습니다.

익명 집계라도 소수 집단, 좁은 날짜·직종, 공개 이슈 링크를 조합하면 개인을 추정할 수 있습니다. 식별 가능성이 있으면 기간·범주를 넓히거나 공개를 보류합니다. 익명화가 재식별을 완전히 막는다고 보장하지 않습니다. 동의 철회가 확인되면 관리 가능한 공개 설명도 수정합니다. Git 이력이나 이미 배포한 보고서·자료까지 완전히 회수할 수 있다고 약속하지 않습니다.

## CSV 기록 규칙

한 행은 한 사람의 한 사용 사례 또는 하나의 확인된 기여·재사용 사건입니다. 후속 답변과 수정 확인은 같은 `case_id`를 갱신합니다. 다른 버전의 별도 실행은 새 사례로 기록할 수 있지만 고유 테스터 수는 같은 `participant_id`를 한 번만 셉니다. 두 ID는 임의 식별자이며 이름·이메일·계정명에서 만들지 않습니다. 신원 대조에 필요한 정보는 공개하지 않습니다.

| 열                                                 | 의미와 허용 값                                                                                                                               |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `case_id`, `participant_id`                        | 변경하지 않는 사례 ID와 참여자 ID. 중복 제거와 동일 참여자 확인에 사용                                                                       |
| `observed_on`, `recorded_on`                       | 실제 실행·사건 날짜와 기록 날짜, `YYYY-MM-DD`; 모르면 비워 두고 추정하지 않음                                                                |
| `period_start`, `period_end`                       | 집계 기간의 시작·끝, `YYYY-MM-DD`; 날짜 포함 범위를 보고서에 명시                                                                            |
| `version_or_commit`                                | 사용한 릴리스 또는 커밋. 모르면 `unknown`                                                                                                    |
| `evidence_type`                                    | `demo_test`, `bug_report`, `merged_pr`, `code_reuse`                                                                                         |
| `evidence_url`                                     | 내용을 실제 열어 확인한 이슈·병합 PR·재사용 근거 링크. 임의 링크를 만들지 않음                                                               |
| `industry`, `scenario`, `outcome`, `use_again`     | 양식에서 선택한 업종·작업·결과·재사용 의향. 선택값만 기록하며 자유 서술을 복사하거나 상업용 집계를 위해 임의 재분류하지 않음. 미응답은 빈 값 |
| `external_status`                                  | `external`, `maintainer`, `automation`, `unknown`. 관계가 불명확하면 `unknown`                                                               |
| `verification_status`                              | `self_reported`, `reproduced`, `verified_link`, `unverified`. 유지관리자의 재현이 외부 사용자 성공을 입증하지는 않음                         |
| `permission_verification`                          | `verified`, `pending`, `withdrawn`; 근거를 읽어 범위를 확인한 경우만 `verified`                                                              |
| `evidence_consent`                                 | `yes`, `no`, `pending`, `withdrawn`; 신청 근거용 익명 집계 동의                                                                              |
| `public_case_permission`                           | `yes`, `no`, `pending`, `withdrawn`; 집계 동의를 복사하지 않음                                                                               |
| `commercial_aggregate_consent`                     | `yes`, `no`, `pending`, `withdrawn`; 네 필드의 상업용 익명 집계 동의                                                                         |
| `consent_protocol_version`, `consent_submitted_on` | 동의를 받은 규약 버전 `v1`과 이슈 제출일 `YYYY-MM-DD`. 현재 규약을 과거 동의에 덮어쓰지 않음                                                 |
| `consent_evidence_url`                             | 동의 선택·범위를 확인할 수 있는 근거. 비공개 근거 링크를 공개 CSV에 노출하지 않음                                                            |
| `followup_url`                                     | 관련 수정 이슈·PR 또는 후속 확인 링크. 없으면 빈 값                                                                                          |
| `duplicate_of`                                     | 중복이면 최초 사례의 `case_id`; 별도 실적으로 집계하지 않음                                                                                  |

CSV에 쉼표·줄바꿈이 포함되면 해당 값을 CSV 규칙에 맞게 따옴표로 감쌉니다. 근거가 없거나 확인이 덜 된 항목은 빈 값 또는 `unknown`·`pending` 등 해당 열의 상태로 남깁니다. 성공·외부 사용자·동의를 기본값으로 채우지 않습니다.

## 주 1회 수동 검토

자동 방문 추적, 연락처 수집 또는 백그라운드 보고를 추가하지 않습니다. 주 1회 유지관리자가 새 피드백을 읽고 다음을 확인합니다.

1. 사건 날짜·버전·직접 실행 여부·외부 관계·중복·동의 범위를 확인하고 해당 사례를 갱신합니다. 실제 PR 병합과 코드 재사용은 원본 링크를 열어 검증합니다.
2. 집계에는 해당 용도의 동의가 `yes`이고 권한 확인이 `verified`인 사례만 포함합니다. 각 선택 이용의 `v1`·제출일·12개월 유효 기간과 최신 철회 댓글을 확인하고 허락된 항목만 씁니다. 두 집계는 네 필드만 사용합니다. 외부 사용 지표에서는 내부·자동화·불명확한 관계와 중복을 제외합니다. 개별 공개 허용만 있고 해당 집계 동의가 없는 사례도 집계하지 않습니다. 병합 PR·재사용 프로젝트의 공개 사실은 원본 링크로 검증하고, 개인 사례 인용에는 별도 허용을 확인합니다.
3. 모집 기간·경로·대상 버전은 사전에 정한 조사 배경으로 설명합니다. 개인별 날짜·버전·소요시간을 추가 집계 항목이나 교차분석 차원으로 사용하지 않으며, 그런 분석에는 별도 허락이 필요합니다. 고유 참여자 수와 실행 사례 수를 따로 쓰고, 결과 미응답·중도 포기·실패도 숨기지 않습니다. 작업 성공률은 같은 조사에서 같은 작업을 실제 시도하고 결과를 보고한 동의 사례를 분모로 쓰며, 제외한 미응답 수와 이유를 함께 밝힙니다. 이 수치를 전체 방문자 성공률로 표현하지 않습니다.
4. 작은 표본은 수와 분모를 함께 제시하고 일반적인 성능이나 시장 수요로 확대하지 않습니다. 검증된 실적이 아직 없으면 확인된 근거가 없다고 적습니다. 빈 서식은 0명의 실제 사용자가 존재한다는 조사 결과가 아닙니다.
5. 신청서에는 허용받고 확인한 기간별 수치·사례·링크만 옮깁니다. 계획은 계획으로 남기며, 실제 사용 증거가 생겨도 프로그램의 최신 자격 조건 충족이나 선정이 자동으로 보장되지는 않습니다.
